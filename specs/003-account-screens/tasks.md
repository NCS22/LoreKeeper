- NFR-1 (keyboard), NFR-2 (screen reader announces errors and focus moves), NFR-3 (contrast and visible focus, including error states) on the sign-up and sign-in pages, the user menu, the sign-out action, the not-found page and the error page.

- Handed over by spec 002: **002 FR-29** — set `BETTER_AUTH_URL=https://localhost:3000`, serve over HTTPS, create an account, check in the browser tools that the session cookie has `Secure`, `HttpOnly`, `SameSite=Strict` and the `__Secure-` prefix, then repeat with `http://localhost:3000` and confirm there is no `Secure`; **002 FR-31** — create an account, stop the application, `docker compose restart postgres`, wait until healthy, start the application, reload (the session is still valid), sign out and sign in again.

## Margin and risk

10 of 10 tasks, no margin. The likely overruns are **T6** (three framework reliances to verify first, the proxy scope of the cookie plugin and the first real run of the guard), **T4** and **T5** (every state of a form plus its browser tests) and **T8** (menu, sign-out, back action and clean start). If any of them does not fit in its 20 to 30 minutes, or if T6 finds that D2 needs the user's approval for a spec 002 edit, the implementer stops and proposes splitting the spec into **003 (access: rules, guard, renewal, headers)** and **003b (screens: forms, user menu, not-found and error pages)**, with 003b depending on 003, as the user decided on 2026-11-08. No eleventh task is created.
