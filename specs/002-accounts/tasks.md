## Rules for every task

- Agents never read, print, edit or commit `.env` files. The real `.env` is created by the user. `.env.example` holds names and placeholders only. If a step needs a value that is only in `.env` (or `.env` does not exist yet), the implementer stops and reports; it does not look for the value. No `dotenv` dependency is approved: environment variables are loaded with what the tools already offer (Node's `process.loadEnvFile` / `--env-file`, Vite's `loadEnv` in `vitest.config.mts`, which reads the file as tool configuration, not as an agent). If that does not work, stop and ask (CLAUDE.md "ASK FIRST").
- Commands that are allowed: `docker compose up -d`, `docker compose stop`, `docker compose ps`, `pnpm prisma generate`, `pnpm prisma migrate dev`. Not allowed without asking the user: `docker compose down -v`, deleting volumes, dropping the development database, any push or history rewrite.
- Database-backed tests fail loudly when the database is not reachable; they are never skipped (D24).
- Package names, option names and call names of Better Auth and Prisma come from the plan's memory of their documentation and were not verified. Wherever a task uses them, the implementer checks the installed package first; if a name, a behavior or a version conflicts with the plan, it stops and reports before working around it.
- Spoiler suite: not required in any task (no query, visibility or reading-progress code is touched; spec "Spoiler impact: None").

## Before T1: what the user must prepare by hand

1. Docker Desktop installed and running (needed by T1 and by every later task, because `pnpm test` now includes database-backed tests).
2. A real `.env` in the repository root, created by the user (not by an agent), with values of the user's choosing for: `DATABASE_URL`, `TEST_DATABASE_URL`, `BETTER_AUTH_SECRET` (a long random string), `BETTER_AUTH_URL` (for example `http://localhost:3000`) and the Postgres credentials used by Docker Compose. The exact variable names for the Compose credentials are fixed by T1 in `.env.example`; if `.env` is missing when T1 needs it, T1 stops after writing `.env.example` and `docker-compose.yml` and asks the user to copy the example to `.env` and fill it in.
3. After T1 the user does nothing else by hand until the manual checks at the end (HTTPS and real restart).
