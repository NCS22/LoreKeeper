# Criticality inventory - LoreKeeper

Living document: every production file of the repository, grouped into entries, with its criticality level, the reason for it, the testing strategy and its protection status. Created by spec 005a; kept current by every task that adds, moves or reclassifies a production file.

## How to read it

- **Levels.** `CORE`, `IMPORTANT` and `TIER 0` are defined in the skill `.claude/skills/quality-testing-core/SKILL.md` (section "Levels and how to classify"), together with the reclassification rule. This file does not restate the definitions; it only applies them.
- **One entry per component or per cohesive group** of files that share level and strategy. Every production file matches exactly one entry; an unmatched or duplicated file is a defect, fixed in the task that finds it.
- **Columns.**
  - `Id`: area prefix and number (for example `ACC-3`). Ids are stable; a removed entry leaves its id unused.
  - `Files`: repository-relative glob patterns, one per line (separated by `<br>`), each in backticks. The coverage report script reads this column, so it holds only patterns.
  - `Responsibility`: what the component does, in one sentence.
  - `Level`: `CORE`, `IMPORTANT` or `TIER 0`.
  - `Why`: the reason for the level.
  - `Strategy`: test types and what they must protect.
  - `Protection`: measured lines and branches by test type with the date of the snapshot (for example `2026-11-23: unit 92/85, database 40/30, combined 95/88`), or `protected by browser test <name>`.
  - `Exceptions and floors`: a target override with its reason, or a floor with the plan to raise it, in the written forms of "Exceptions" below, or `-`. The coverage report script reads this column.
- **Coverage targets** are quality goals, not quotas, on **lines and branches** of each entry (the entry is the sum of its files): `CORE` 100 %, `IMPORTANT` 80 %, `TIER 0` none. Statements and functions are not part of the policy. A test that exercises several components counts toward each of them.
- **Exceptions.** When a target cannot be reached without redundant, fragile or low-value tests, the entry records an override in its `Exceptions and floors` cell, written exactly as `override: lines 100, branches 92, reason: <why>`, with both metrics. An IMPORTANT entry below its target that no small test of behavior brings to it, a component reclassified upward included, records a floor, written exactly as `floor: lines 74.4, branches 71.9, plan: <how it is raised>`, with the figure as printed of each metric below its target (a metric at its target, or with nothing to measure, is left out); the plan is usually "raise it when the component is next touched". Figures have one decimal at most, and an entry carries at most one of the two records. A CORE entry never records a floor: it reaches 100 % or records an override. The report script requires the override, else the floor, else the target of the level, and fails on a record that is not in its written form or on a floor in a CORE entry.
- **Coverage figures.** The `Protection` column keeps a dated snapshot; the live figures come from `pnpm test:coverage`, which ends by printing, per entry, lines and branches for the `unit`, `database` and `component` test types and combined, the level, the required figure and the distance to it, plus the overrides and floors in use and the unmatched and duplicated files. End-to-end tests are shown as "not measured": the behaviors they alone protect are named in the entry.
- **Thresholds are active.** Since spec 005b, `pnpm test:coverage` fails, after printing everything, when a CORE or IMPORTANT entry is below its required figure (the combined figure as printed, one decimal), when an override or floor is not in its written form, or when a production file matches no entry or more than one. A figure above its floor or override prints a notice and fails nothing, but the validation of a spec requires that no such notice remains: the record is raised to the new figure, or removed when the entry reaches its target. The command is required at the validation of a spec, not at each task; `pnpm test` never fails on coverage.
- **Authority order.** The constitution (`CLAUDE.md` and `.claude/rules/*`) prevails over the skill, and the skill prevails over this inventory. When this file contradicts either, the file is wrong and is fixed in the same task.
